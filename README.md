# Nexora — CRM для малого и среднего бизнеса

Лиды, переписка из мессенджеров, сделки, клиенты, задачи, счета, планы продаж, аналитика и автоматизации в одном месте. Запуск за пять минут, без внедрения и платных виджетов.

Сейчас это рабочий MVP в **демо-режиме**: весь интерфейс работает, данные генерируются автоматически и хранятся в браузере. Схема базы данных, серверная проверка прав и разделение данных компаний уже готовы — следующий шаг — подключить их к интерфейсу (см. «Что дальше»).

## Как запустить на своём компьютере

Понадобится только Node.js — программа, которая запускает проект.

1. **Установите Node.js.** Скачайте версию LTS (20 или новее) с [nodejs.org](https://nodejs.org) и установите как обычную программу.
2. **Распакуйте архив** с проектом в любую папку, например «Документы/nexora».
3. **Откройте терминал в этой папке.**
   - macOS: правый клик по папке в Finder → «Службы» → «Новый терминал по адресу папки».
   - Windows: откройте папку в проводнике, в адресной строке напишите `cmd` и нажмите Enter.
4. **Установите зависимости** — один раз, займёт 1–2 минуты:
   ```bash
   npm install
   ```
5. **Запустите проект:**
   ```bash
   npm run dev
   ```
6. Откройте в браузере **http://localhost:3000** — это лендинг. Кнопка «Посмотреть демо» ведёт в CRM, «Начать бесплатно» — в регистрацию и онбординг.

Чтобы остановить проект, нажмите в терминале `Ctrl + C`.

### Полезно знать про демо-режим

- Демо-данные одинаковые у всех: компания «Атлас Диджитал», 7 сотрудников, 347 клиентов, около 1 000 лидов и 460 сделок за два года истории. Все цифры на главной и в аналитике считаются из этих записей и сходятся между собой.
- Всё, что вы меняете (перетаскиваете сделки, создаёте клиентов, закрываете задачи), сохраняется в этом браузере.
- Вернуть исходное состояние: **Настройки → Компания → Сбросить демо-данные**. Пройти онбординг заново: откройте `/onboarding`.
- Горячие клавиши: `⌘K` / `Ctrl+K` — поиск и команды, `?` — список всех сочетаний, `N` — новая сделка, `G` затем `D` — перейти в сделки.

## Как выложить в интернет (Vercel, бесплатно)

1. Создайте пустой репозиторий на [GitHub](https://github.com) и загрузите в него **содержимое** папки `nexora` (файлы `package.json`, `README.md` и папки `src`, `docs` и другие должны лежать в корне репозитория). Папки `node_modules` и `.next` загружать не нужно.
   - Через сайт: **Add file → Upload files**. За один раз GitHub принимает до 100 файлов, поэтому загружайте частями: сначала файлы из корня и папки `docs`, `drizzle`, `scripts`, потом папку `src` (её тоже можно частями: `src/app`, `src/components`, остальное).
   - Проще через [GitHub Desktop](https://desktop.github.com): **File → Add local repository** → выбрать папку `nexora` → **Publish repository**. Загрузится всё сразу.
2. Зайдите на [vercel.com](https://vercel.com), войдите через GitHub и нажмите **Add New → Project**.
3. Выберите репозиторий и нажмите **Deploy**. Настройки менять не нужно — Vercel сам распознает Next.js.
4. Через 1–2 минуты появится ссылка вида `nexora-xxx.vercel.app`. Свой домен подключается в **Settings → Domains**.

Для демо-режима переменные окружения не нужны.

## Подключение базы данных

База понадобится, когда вы будете подключать настоящих пользователей. Для демо её можно пропустить.

1. Создайте базу PostgreSQL: подойдут [Neon](https://neon.tech) или [Supabase](https://supabase.com) (есть бесплатные тарифы), Timeweb Cloud, Yandex Cloud или локальный PostgreSQL.
2. Скопируйте файл `.env.example` в `.env.local` и вставьте адрес базы в `DATABASE_URL`.
3. Создайте таблицы и залейте демо-данные:
   ```bash
   npm run db:migrate
   npm run db:seed
   ```
4. Посмотреть данные в удобном интерфейсе: `npm run db:studio`.

Проверить схему **без установки PostgreSQL** можно одной командой — она поднимет базу в памяти, применит миграции, зальёт демо-данные и проверит, что база не даёт смешать данные разных компаний:

```bash
npm run db:check
```

| `npm run db:studio` | Просмотр базы в браузере |

## Что внутри

**Разделы CRM:** главная с KPI и блоком «Требует внимания», входящие (переписка из Telegram, WhatsApp, MAX и VK с шаблонами ответов, AI-черновиком и сводкой), сделки (канбан с перетаскиванием и таблица), лиды из всех каналов со скоростью ответа, клиенты с полным профилем, задачи, аналитика (продажи, выручка, LTV, лиды, сотрудники, источники, конверсия), команда, роли и планы продаж, автоматизации с визуальным конструктором и проверкой на своих данных, AI-ассистент, уведомления, поиск по ⌘K, настройки (профиль, компания и реквизиты, команда, уведомления, внешний вид, безопасность, воронка, свои поля, товары, шаблоны ответов, импорт, интеграции, тариф).

**Удобство в мелочах:**

- Переписка открывается прямо в карточке сделки и клиента. Ответ новому лиду сам переводит его в работу и фиксирует скорость ответа.
- Восемь готовых наборов под сферу (агентство, услуги, розница, клиника, обучение, стройка, производство, другое): этапы воронки, поля, товары, шаблоны ответов и причины отказа. Выбираются в онбординге и меняются в «Настройки → Воронка».
- Товары в сделке → счёт с QR-кодом для оплаты (ГОСТ Р 56042-2014) и сумма прописью или КП в PDF. Отметка оплаты закрывает сделку.
- Импорт из Excel, CSV и выгрузок amoCRM и Битрикс24: колонки сопоставляются сами, дубли по телефону и email пропускаются, импорт отменяется одной кнопкой. Автоматизации при импорте не запускаются.
- Массовые действия в таблицах (этап, ответственный, приоритет, CSV, удаление) — панель появляется, только когда строки отмечены; Shift+клик выделяет диапазон.
- Сохранённые виды списков рядом с фильтрами «Все / Мои / …».
- План продаж на месяц для каждого менеджера с темпом выполнения — в «Команде», на главной и в аналитике.

**Сайт:** лендинг с живой доской сделок на первом экране, страница тарифов, вход, регистрация, онбординг из пяти шагов.

**Технологии:** Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, компоненты в стиле shadcn/ui на Radix, иконки Lucide, графики Recharts, перетаскивание dnd-kit, PostgreSQL + Drizzle ORM, валидация zod.

Подробнее об устройстве — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Разбор amoCRM и Битрикс24 и чем Nexora от них отличается — в [docs/COMPETITORS.md](docs/COMPETITORS.md).

## Честно о текущем состоянии

| Что | Состояние |
|---|---|
| Интерфейс всех разделов, тёмная тема, мобильная версия | Готово |
| Демо-данные и расчёт метрик | Готово, работает в браузере |
| Схема базы, миграция, заливка демо-данных | Готово (`drizzle/`, `src/db/`) |
| Сессии, проверка прав и компании на сервере | Готово как основа (`src/server/`), образец — действия со сделками |
| Вход и регистрация | Формы готовы, настоящие аккаунты — следующий шаг |
| Входящие и переписка | Интерфейс, шаблоны и AI-черновик готовы; в демо клиент «отвечает» сам. Приём сообщений из мессенджеров — следующий шаг (таблицы `conversations`, `messages` готовы) |
| Счета и КП | Готово: PDF через печать браузера, QR для оплаты, нумерация, отметка оплаты |
| Импорт | Готово в браузере: CSV (UTF-8 и Windows-1251), XLSX, HTML-выгрузки Битрикс24 |
| Интеграции (Telegram, WhatsApp, MAX, почта, сайт) | Экран подключения готов, сами подключения — следующий шаг |
| AI-ассистент | Отвечает по данным CRM по правилам; подключение языковой модели — следующий шаг |
| Оплата | Тарифы в конфиге, таблица подписок готова; платёжный провайдер не подключён |
| Отзывы на лендинге | Пусто намеренно: блок приглашает в пилот и сам покажет отзывы, когда вы добавите их в `src/config/landing.ts` |

Цены тарифов (`src/config/plans.ts`) — ориентир для MVP, меняются в одном файле.

## Что дальше

1. Регистрация и вход на `src/server/session.ts` (таблицы `users`, `sessions`, `oauth_accounts` уже есть), хеш паролей — argon2id.
2. Перевести экраны со стора демо-режима на серверные действия по образцу `src/server/actions/deals.ts`.
3. Приём заявок и сообщений: вебхук для формы сайта, Telegram-бот, MAX и WhatsApp через официальные API. Входящие пишутся в `conversations` / `messages`, повторная доставка вебхука отсекается по `external_id`.
4. Платежи: ЮKassa или CloudPayments для России, Stripe — для зарубежа (таблица `subscriptions` уже готова).
5. AI-ассистент на языковой модели с доступом только к данным своей компании.
